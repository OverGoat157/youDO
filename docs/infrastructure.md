# Каркас КР №2

Требуются JDK 21 и Maven 3.9+. Проверьте `java -version` и `mvn -version`: Maven должен использовать тот же JDK 21 через `JAVA_HOME`.

## Запуск

1. Используйте PostgreSQL с базой `youdo` из КР №1. Для новой **отдельной демонстрационной базы** можно выполнить `sql/schema.sql`, затем `sql/seed.sql`. Эти скрипты удаляют прежние данные; приложение никогда не запускает их самостоятельно.
2. Скопируйте `src/main/resources/db.properties.example` в `src/main/resources/db.properties`. Укажите адрес, реальный опубликованный порт PostgreSQL, пользователя и пароль. Файл исключён из Git и итогового JAR.
3. Из корня репозитория:

```sh
mvn test
mvn clean package
mvn javafx:run
```

Основной запуск — `mvn javafx:run`, главный класс — `ru.mirea.freelance.fx.FxApplication`. JAR не содержит зависимости и не предназначен для прежнего запуска `java -jar`. Maven копирует FXML и CSS в classpath, а локальный конфиг доступен приложению в `target/classes`.

Для отдельного подключения поддерживается `mvn -Dyoudo.db.config=/path/to/db.properties javafx:run`. Maven передаёт параметр в JVM приложения; `DatabaseManager` читает этот файл вместо ресурса classpath. Пустой параметр сохраняет обычное поведение. [Docker-стенд](docker-local.md) использует `docker/db.properties`, не перезаписывая конфиг КР №1.

Если главный экран отсутствует, открывается `startup.fxml` с вкладками пользователей и статистики; при переходе данные обновляются. Когда в ресурсах появится `/ru/mirea/freelance/fx/main.fxml`, приложение загрузит его. Общий `/ru/mirea/freelance/fx/app.css` подключается к Scene, когда файл добавлен. Главное окно заказов, пользователи и общий CSS включены; итоговый прогон описан в review.md.

## Контракты для экранов

Контроллеры имеют публичный конструктор `(AppContext context)`. `context.load("/ru/mirea/freelance/fx/order-form.fxml")` возвращает **уже загруженный** `FXMLLoader`; корень — `getRoot()`, контроллер — `getController()`. Единая controllerFactory действует и внутри `fx:include`.

Контекст содержит `users()`, `orders()`, `statistics()`, `tasks()`, `exportAction()`. Он создаётся один раз и соединяет существующие JDBC-репозитории с сервисами. Создание контекста читает только локальную конфигурацию; подключение к серверу происходит при вызове репозитория.

```java
// Скопировать значения полей до передачи работы в фон.
context.tasks().run(
    () -> context.users().findAll(),
    users -> { /* UI-поток: обновить таблицу и снять занятость */ },
    error -> { /* UI-поток: снять занятость, Dialogs.error(owner, error.getMessage()) */ }
);
```

Контроллер блокирует повторное действие и показывает занятость до обоих callback. Не читайте UI-поля из `work`; обновляйте ObservableList и окна только в callback. Один рабочий поток последовательно выполняет операции; при закрытии приложения `FxTasks.close()` прерывает работу, очищает очередь и подавляет запоздавшие callback. Поток daemon, поэтому зависшая операция не удержит процесс после закрытия окна.

Общие диалоги: `Dialogs.error(Window, String)` и `Dialogs.confirmDelete(Window, String)`. Экспорт: `context.exportAction().exportOrders(owner, currentOrders(), usersSnapshot)` — передавайте видимые заказы в текущем порядке и список пользователей.

## JDBC и демонстрационные данные

`DatabaseManager` проверяет наличие `db.url`, `db.user`, `db.password`. Каждая операция получает своё соединение и закрывает его через try-with-resources. У драйвера заданы connectTimeout 5 секунд и socketTimeout 15 секунд. Сообщения подключения не раскрывают пароль и сырой текст драйвера.

В `JdbcUserRepository` SQLSTATE `23505` переводится в сообщение о занятом email, `23503` — о связанных заказах, включая завершённые. Проверки сервисов сохраняются; ограничения самой БД защищают в том числе от конкурентных операций.

В seed 6 пользователей и 12 заказов: разные категории, все статусы, неназначенные исполнители. Дедлайны относительно `CURRENT_DATE`: 5 будущих и 3 просроченных активных заказа. Перезагрузка seed меняет даты относительно нового дня, а не пересоздаёт базу при каждом запуске приложения.

## Проверки

Обычные тесты не требуют дисплея или работающей БД. Для проверки настоящего FXML, фоновых задач и UI-callback:

```sh
xvfb-run -a mvn -Dyoudo.fx.tests=true test
```

На компьютере с графическим сеансом достаточно `mvn -Dyoudo.fx.tests=true test`. Для JDBC сначала подготовьте отдельную БД схемой и seed, создайте отдельный properties-файл и выполните:

```sh
mvn -Dyoudo.db.tests=true -Dyoudo.test.db.config=/absolute/path/check-db.properties test
```

Интеграционный тест создаёт собственные записи с уникальными email и удаляет их в `finally`. Проверяет CRUD, nullable исполнителя, BigDecimal, даты, поиск, статусы, связи и сообщения UNIQUE/FK. Схему или seed он не запускает.

Проверено 20.10.2026: JDK 21, Maven 3.9.9, JavaFX 21.0.8; сборка и 91 тест прошли без пропусков, включая 3 JavaFX-проверки и интеграционный сценарий на PostgreSQL 16. В отдельной БД выполнены schema и seed: 6 пользователей, 12 заказов, 3 просроченных активных и 5 будущих. Проверены чтение, создание, обновление, удаление, nullable исполнитель, точность денег, даты и сообщения UNIQUE/FK. Отдельно проверены настоящее окно, 13 показателей на тестовой БД, доступность интерфейса после ошибки подключения, диалог отсутствующей конфигурации и запуск `mvn javafx:run`. Демонстрационный архив преподавателя проверяется отдельно, см. `docker-demo.md`.
