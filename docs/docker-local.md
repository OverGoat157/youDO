# Docker для youDO

Наш стенд запускает PostgreSQL 16 с демонстрационными данными. JavaFX подключается к нему через JDBC; окно открывается на компьютере пользователя. Дополнительный контейнер содержит JDK 21, Maven 3.9.9, библиотеки JavaFX и виртуальный дисплей Xvfb для полного прогона тестов.

Это собственное окружение проекта. Статус отдельного REST-примера преподавателя описан в [docker-demo.md](docker-demo.md).

## Первый запуск

Нужны работающий Docker с Compose v2+ и Python 3. Команды выполняются из корня репозитория:

```sh
python3 docker/setup.py
docker compose up -d --wait db
docker compose ps
```

Скрипт создаёт `.env` со случайным паролем и отдельный `docker/db.properties`. Оба файла исключены из Git, сборочного контекста Docker и JAR. Повторный запуск сохраняет `.env` и обновляет JDBC-файл по фактическим настройкам Compose. Существующий `src/main/resources/db.properties` не меняется.

Адрес по умолчанию — `127.0.0.1:55432`, база и пользователь — `youdo`. Порт опубликован только на локальном интерфейсе. Если порт занят, измените `YOUDO_DB_PORT` в `.env`, повторите `python3 docker/setup.py` и `docker compose up -d --wait db`.

При первом запуске на новом volume автоматически выполняются `sql/schema.sql` и `sql/seed.sql`: появляются 6 пользователей и 12 заказов. Healthcheck ждёт сервер с доступным TCP-портом после инициализации. Существующий PostgreSQL на компьютере не затрагивается.

## Открыть приложение

В графическом сеансе, с локальными JDK 21 и Maven 3.9+:

```sh
mvn -Dyoudo.db.config=docker/db.properties javafx:run
```

Проверьте `mvn -version`: Maven должен использовать JDK 21 через `JAVA_HOME`. Docker не выводит окно приложения на экран. Параметр `youdo.db.config` передаёт путь к внешнему файлу в JVM JavaFX. Без него действует прежний конфиг из classpath; неверный явно заданный путь вызывает ошибку, а не подключение к другой базе.

## Проверить весь проект в контейнере

Локальные Java, Maven и дисплей для этого не нужны:

```sh
docker compose --profile test build verify
docker compose --profile test run --rm verify
```

Контейнер работает от пользователя с UID 10001, подключается к сервису `db` по внутренней сети и выполняет `clean verify` с включёнными JavaFX- и JDBC-тестами. Код берётся из образа: после изменения исходников повторите сборку. При первой сборке и первом прогоне нужен интернет для образов, системных пакетов и Maven-зависимостей. Maven-кэш сохраняется в отдельном volume.

Интеграционные тесты создают и удаляют собственные временные записи; schema/seed повторно не загружаются. Конфигурация для тестовой JVM создаётся внутри контейнера и удаляется вместе с ним. Итог и границы проверки — в [review.md](review.md).

## Остановка и данные

```sh
docker compose logs --tail=50 db
docker compose down
docker compose up -d --wait db
```

`down` сохраняет данные в volume `youdo-kr2_postgres_data`. Повторный `up` использует прежние записи. Не добавляйте `-v`, если данные нужны. Сохраните `.env`: смена пароля, имени базы или пользователя в этом файле не перенастраивает уже созданную БД. Для таких изменений требуется отдельно изменить реквизиты внутри PostgreSQL и повторить setup.

Инициализация только пустого каталога данных и хранение PostgreSQL 16 в `/var/lib/postgresql/data` соответствуют [документации официального образа PostgreSQL](https://hub.docker.com/_/postgres). Образ проверок основан на [официальном Maven с Eclipse Temurin 21](https://hub.docker.com/_/maven).
