# Сценарий предзащиты КР №2

Перед показом: JDK 21, Maven 3.9+, рабочая отдельная демонстрационная БД, заполненный локальный `db.properties`. Не запускайте schema/seed поверх рабочих данных команды. Дедлайн для нового заказа выберите в будущем относительно дня показа.

1. `mvn javafx:run`: главное окно с тремя вкладками и общим CSS. На «Заказах» видны имена пользователей, бюджет и дедлайн.
2. Создайте отдельного заказчика на вкладке «Пользователи». Откройте редактирование, поменяйте имя и сохраните. Повторный email должен оставить форму открытой и объяснить ошибку. Отмена редактирования не сохраняет ввод.
3. На «Заказах» создайте заказ: выберите заказчика по имени/email, категорию, бюджет с копейками и будущий дедлайн. Сначала введите `12,345` — сервис отклонит лишние копейки; затем исправьте на `12,34` и сохраните.
4. Выберите строку: появляется описание. Откройте изменение — поля заполнены, заказчик показан как связанный пользователь. Измените название и бюджет. Статус и исполнитель меняются отдельными действиями.
5. Назначьте исполнителя из FREELANCER. Проведите заказ через IN_PROGRESS → ON_REVIEW → IN_PROGRESS (доработка) → ON_REVIEW → COMPLETED. Для нового неназначенного заказа попытка IN_PROGRESS даёт понятную ошибку.
6. Найдите слово только из описания, затем задайте вместе текст, статус и категорию. Проверьте регистр, отсутствие совпадений, счётчик и «Сбросить». «Обновить» сохраняет текущие условия.
7. Щёлкните бюджет и дедлайн в обе стороны. После обновления фильтры, сортировка и выбранная запись сохраняются, если запись осталась в результате.
8. Экспортируйте отфильтрованный результат через «Экспорт CSV». Проверьте имя файла, порядок строк, бюджет, кириллицу и имена заказчика/исполнителя. Отмена FileChooser не создаёт файл. Пустой результат экспортируется только с заголовками.
9. Откройте «Статистику»: 13 показателей относятся ко всей базе. После изменения данных переход на вкладку пересчитывает их. Средний бюджет и суммы считаются через BigDecimal.
10. Проверьте связанную роль пользователя: смена роли заказчика или исполнителя существующих заказов запрещена. Активные связи блокируют удаление в сервисе; ссылки из завершённых заказов защищает FK.
11. Удалите тестовый заказ: сначала отмените подтверждение, затем подтвердите. После удаления связанных заказов можно удалить тестового пользователя.
12. Перезапустите приложение и убедитесь, что оставленные данные прочитаны из БД. Объясните цепочку Controller → Service → Repository → JDBC и границы фонового/UI-потоков.

Для проверки недоступной БД используйте отдельное тестовое подключение, без остановки общей БД команды: окно показывает причину и остаётся доступным. Проверьте форму с пустым названием, буквами в бюджете, датой `31.02.<будущий год>` и прошедшим дедлайном; ввод сохраняется.

Docker-пример преподавателя показывается отдельно по `docker-demo.md` после получения архива. Не представляйте проверку собственного PostgreSQL как запуск его backend и REST-клиента.
