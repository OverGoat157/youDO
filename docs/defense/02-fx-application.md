# 2. `FxApplication`: от `launch` до окна

[Назад: Maven](01-maven.md) · [Оглавление](README.md) · [Дальше: AppContext](03-app-context.md)

Открой [FxApplication.java](../../src/main/java/ru/mirea/freelance/fx/FxApplication.java). Это точка входа **JavaFX-части** приложения.

## Жизненный цикл

Класс объявлен `extends Application`. Его `main(String[] args)` вызывает `launch(args)`. JavaFX создаёт своё окружение и вызывает `start(Stage stage)`. После закрытия приложения вызывается `stop()`, где закрывается `AppContext` и его фоновые задачи.

`start` получает главный `Stage` от JavaFX. Мы не создаём его через `new Stage()`. Новые `Stage` создаются позже для диалоговых форм.

Порядок строк в `start`:

1. `new AppContext()` собирает доступ к базе, сервисы и фоновые задачи. Конструкторы не делают SQL-запрос; подключение открывается при операции репозитория.
2. Проверка `main.fxml` выбирает главный экран. `startup.fxml` — запасной экран, оставшийся от раннего каркаса. Сейчас `main.fxml` есть и выбирается он.
3. `context.load(...)` через `FXMLLoader` читает FXML, создаёт элементы и контроллеры и возвращает загруженный корень.
4. `new Scene(loader.<Parent>getRoot(), 1100, 720)` делает сцену с этим корнем и начальным размером.
5. Если найден `app.css`, его URL добавляется к сцене.
6. У `Stage` задаются заголовок, минимальные размеры и сцена; `stage.show()` делает окно видимым.

`loader.<Parent>getRoot()` означает, что результат обобщённого метода нужен как `Parent`. В `main.fxml` корень — `TabPane`, то есть контейнер элементов интерфейса.

## Stage, Scene, Node

```text
Stage — окно с заголовком и размерами
  └─ Scene — содержимое окна
       └─ корневой Node / Parent
            ├─ таблица
            ├─ кнопки
            └─ контейнеры и другие элементы
```

`Stage` отвечает за окно. `Scene` хранит дерево элементов и CSS. `Node` — элемент дерева: `Button`, `TableView`, `Label`, `TabPane`, `VBox` и другие. `TabPane` является узлом; отдельный объект `Tab` не является `Node`, но может содержать узлы.

`setScene(scene)` помещает содержимое в окно, а `show()` показывает окно. Если пропустить `show()`, окно не появится.

## Ошибка при старте

Если при создании контекста или загрузке интерфейса возникнет `RuntimeException`, блок `catch` закрывает созданный контекст, показывает диалог с сообщением и вызывает `Platform.exit()`. При штатном закрытии срабатывает `stop()`. Закрытие контекста останавливает `FxTasks`.

Важно не путать две ситуации: чтение настроек БД происходит при создании `DatabaseManager`; само подключение и SQL начинаются при вызове метода репозитория. Поэтому окно может появиться даже при недоступном PostgreSQL, после чего экран покажет ошибку загрузки данных.

## Что сказать вслух

> Maven запускает `FxApplication`. Метод `main` вызывает JavaFX `launch`, JavaFX вызывает `start` и передаёт главный `Stage`. В `start` загружается FXML, его корень помещается в `Scene`, сцена устанавливается в окно, а `show()` показывает его. При завершении `stop()` освобождает ресурсы приложения.

## Проверка понимания

1. Кто вызывает `start` и откуда берётся главный `Stage`?
2. Что будет, если вызвать `setScene`, но не `show`?
3. Что вернёт `getRoot()` для нашего `main.fxml`?
4. Почему отсутствие PostgreSQL не обязательно мешает появлению окна?

<details>
<summary>Ответы для самопроверки</summary>

1. JavaFX после вызова `Application.launch`; главный `Stage` создаёт и передаёт JavaFX.
2. Сцена будет привязана к окну, но окно не станет видимым.
3. Корневой `TabPane` как `Parent`.
4. Конструкторы читают конфигурацию, а соединение создаётся позже при запросе через JDBC-репозиторий.
