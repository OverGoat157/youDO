# youDO — биржа фриланса

Настольное приложение JavaFX для КР №2 по дисциплине «Программирование корпоративных систем», продолжение проекта КР №1. Пользователи и заказы хранятся в PostgreSQL; приложение подключается к своей базе напрямую через JDBC.

Команда ЭФБО-17-24: Епифанов Денис, Джумагулов Карим, Гришутина Ангелина, Васин Сергей, Елисеев Юрий.

## Возможности

- Вкладки «Заказы», «Пользователи», «Статистика» с обновлением данных из БД.
- Создание, редактирование и удаление заказов и пользователей через формы; удаление требует подтверждения.
- Выбор заказчика и исполнителя по имени и email; отдельные действия назначения и смены статуса.
- Поиск по названию **или** описанию вместе с фильтрами по статусу **и** категории. «Обновить» сохраняет условия, «Сбросить» снимает их.
- Числовая сортировка бюджета и календарная сортировка дедлайна в обе стороны с сохранением после обновления.
- Экспорт видимых заказов в CSV через выбор файла: текущие фильтры и порядок строк сохраняются, кириллица — UTF-8 с BOM.
- 13 показателей статистики по всей базе, включая средний бюджет, активные бюджеты и просроченные заказы.

## Требования

- **JDK 21**, Maven **3.9+**. Проверьте `java -version` и `mvn -version`: Maven должен использовать JDK 21 через `JAVA_HOME`.
- PostgreSQL 14+ с базой `youdo` из КР №1 либо наш Docker-стенд с PostgreSQL 16; JDBC-драйвер поставляется Maven.
- Графический сеанс для JavaFX. Для автоматических проверок в Linux без дисплея используется Xvfb.

Приложение немодульное. JavaFX 21.0.8, PostgreSQL JDBC, Apache POI и JUnit 5 объявлены в `pom.xml`.

## Подготовка базы

Готовое окружение с отдельной БД и демонстрационными данными:

```sh
python3 docker/setup.py
docker compose up -d --wait db
mvn -Dyoudo.db.config=docker/db.properties javafx:run
```

Для этого нужны Docker с Compose и Python 3, а для окна — JDK 21 и Maven 3.9+. Настройки прежней БД не меняются. Полный прогон тестов также можно выполнить в контейнере без локальной Java: [инструкция Docker](docs/docker-local.md).

Если база КР №1 уже есть, используйте её и переходите к конфигурации подключения. Приложение не выполняет SQL-скрипты автоматически.

**Только для отдельной новой демонстрационной базы** создайте пользователя и БД от имени администратора PostgreSQL:

```sql
CREATE USER youdo WITH PASSWORD 'CHANGE_ME';
CREATE DATABASE youdo OWNER youdo;
```

Затем загрузите схему и демонстрационные данные:

```sh
psql -h localhost -U youdo -d youdo -f sql/schema.sql
psql -h localhost -U youdo -d youdo -f sql/seed.sql
```

`schema.sql` удаляет прежние таблицы, `seed.sql` очищает записи. Не выполняйте их поверх нужных рабочих данных. В seed — 6 пользователей и 12 заказов, все статусы и категории, пустые исполнители, будущие и просроченные дедлайны относительно дня загрузки.

## Конфигурация и запуск

Из корня репозитория:

```sh
cp src/main/resources/db.properties.example src/main/resources/db.properties
```

На Windows файл можно скопировать проводником или через PowerShell `Copy-Item`. Заполните `db.url`, `db.user`, `db.password` в полученном файле. Укажите реальный опубликованный порт PostgreSQL. Локальный файл исключён из Git и JAR.

```sh
mvn test
mvn clean package
mvn javafx:run
```

Главный класс — `ru.mirea.freelance.fx.FxApplication`. **Основной запуск КР №2 — `mvn javafx:run`.** `target/youdo.jar` не содержит зависимости и не запускается прежней командой `java -jar`. FXML, CSS и локальная конфигурация при Maven-запуске читаются из classpath.

При проблеме подключения окно остаётся доступным и показывает объяснение; после исправления подключения можно нажать «Обновить». В форме заказа есть отдельное обновление списка пользователей. Отсутствующий файл настроек объясняется диалогом при старте.

## Бизнес-правила

Название — до 150 символов, имя — до 100, email — до 150, значения обязательны. Email имеет корректный вид и уникален; собственный email при редактировании допустим. Роль нельзя менять, если это нарушит связи существующих заказов, включая завершённые.

Бюджет положительный, не больше `9999999999.99`, с точностью до копеек: `1.2300` допустим, `1.231` отклоняется. Новый или редактируемый заказ не сохраняется с прошедшим дедлайном. Просмотр просроченных записей разрешён.

Заказчик имеет роль CUSTOMER, исполнитель — FREELANCER; заказчик не может выполнять свой заказ. Переходы:

```text
OPEN → IN_PROGRESS → ON_REVIEW → COMPLETED
        ↑                 │
        └─────────────────┘  доработка
OPEN / IN_PROGRESS → CANCELLED
```

Начать работу без исполнителя нельзя. Удаление пользователя с активными заказами блокирует сервис; ссылки из завершённых записей защищены FK БД и дают понятную ошибку. При ошибке форма и введённые значения сохраняются.

## Тесты

Обычные тесты работают без БД и дисплея:

```sh
mvn test
```

Настоящие JavaFX-экраны и фоновые операции:

```sh
xvfb-run -a mvn -Dyoudo.fx.tests=true test
```

В графическом сеансе `xvfb-run -a` можно убрать. Для полного набора сначала подготовьте **отдельную** тестовую БД и properties-файл, затем:

```sh
xvfb-run -a mvn -Dyoudo.fx.tests=true -Dyoudo.db.tests=true \
  -Dyoudo.test.db.config=/absolute/path/check-db.properties clean package
```

Тесты БД не запускают schema/seed и удаляют только собственные временные записи. Без соответствующих параметров JavaFX- и JDBC-проверки пропускаются явно. Протокол общей проверки и ограничения — [docs/review.md](docs/review.md).

## Архитектура и документы

```text
FXML / CSS → Controller → Service → Repository → JDBC → PostgreSQL
                 ↕
             FxTasks: работа в фоне, callback в JavaFX Application Thread
```

`AppContext` создаёт зависимости один раз. SQL находится в репозиториях, бизнес-правила — в сервисах. Консольное меню и CSV/XLSX-экспортёры КР №1 сохранены; основной интерфейс КР №2 — JavaFX, его экспорт сохраняет один CSV текущей таблицы.
